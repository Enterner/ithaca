# ithaca 前端文案规范（所有 agent 与开发者共用）

> 与 `docs/注释规范.md` 同构的单一事实源。适用面：`ui/src` 全部用户可见文案——
> 标签、按钮、提示、tooltip、占位符、通知、状态行。

## 原则：只说「是什么 / 做什么」，不解释「怎么实现的 / 为什么这样」

界面是操作面不是说明书。凡是向用户解释**机制、口径、耗时、数据来源、内部路径、
副作用**的句子，一律不出现——机制的正确出口是文档与注释，不是界面。

- **删**（解释性，真实存量案例）：
  - 耗时/缓存机制：「转换中…（首次打开需数秒，再次打开走缓存）」
  - 统计口径公式：「缓存率 = 会话内逐轮（命中/输入）的平均，未回报轮不计入」
  - 数据来源：「（无实测回报，总量同为估算）」
  - 内部存储路径：「松开以附加文件（将存入工作区 .ithaca/uploads）」
  - 实现行为与善后指引：「撤回本轮全部痕迹——模型上下文与显示记录一并回退
    （文件改动不回滚，需要时用撤销处理）」
  - 请求机制：「按 Base URL + API Key 请求平台 GET /models（OpenAI 兼容）」
- **留**（操作信息，删了会做错事）：
  - 动作词与状态：「转换中…」「↩ 已撤销」「撤回本轮」
  - 表单填法与必然后果：「已设置（留空 = 不修改）」「支持 1M / 256K / 131072
    直接输入」「套用会覆盖模型列表」
  - 格式约束：「每行 KEY=VALUE」「仅限字母数字下划线连字符」
- **判据一句话**：删掉这句后，用户第一次见到时会不会做出错误操作？不会 ⇒ 删；
  会（填错格式、误以为数据会丢）⇒ 留。
- 图标按钮不得因删解释而裸奔：tooltip 保留动作词（「撤回」），满足可访问性。
- 存量解释性文案遇到即删，随其所在改动的批次提交，不单开一笔。
