# ithaca 测试规范（所有 agent 与开发者共用）

> 本文件是测试写法的**单一事实源**。AGENTS.md 与 write-tests skill 都只留指针到这里。
> 写测试前先定层，层决定位置和写法。所有测试一律收编进 `tests/`，`scripts/` 只放任务入口薄壳。

## 1. 目录与分层职责

| 层 | 位置 | 测什么 | 不测什么 |
|----|------|--------|---------|
| C++ 单测 | `tests/unit/test_<域>.cpp` | 纯逻辑（jail/edit/snapshots/解析器…），秒级 | 网络、落盘时序、跨插件 |
| 回归 golden | `tests/regress/` | 全链输出与基准逐字节一致 | — |
| API e2e | `tests/e2e/<功能>/api.spec.mjs` | 端点契约、生命周期、持久化闭环、重启重放 | 渲染、点击链 |
| UI e2e | `tests/e2e/<功能>/ui.spec.mjs` | 用户可见行为：真实点击、渲染、网络请求面 | 壳本身（窗口/DPI/启动链） |

- **每个功能一个文件夹**（`tests/e2e/sessions/`、`tests/e2e/决策坞/`…），文件夹名 =
  功能域；其内文件按层命名 `api.spec.mjs` / `ui.spec.mjs`（文件夹已带功能名，文件名
  不重复）——只放该域实际需要的层（纯 UI 域可无 api 层），允许子域文件（如
  `conversation/subagent-ui.spec.mjs`），文件名以规范名结尾即可被对应 project 命中。
  **不**按冒烟/全量分层——分层走 `playwright.config.mjs` 的 projects，不进目录结构。
- 测试标题带上方案文档的用例编号（SC1、SC2a…），与 `docs/*-方案.md` 的用例表互查。
- 共享基建只在 `tests/e2e/helpers/`，功能文件夹从 `../helpers/` 引用；两个 spec
  之间不许互相 import。
- 内核边界纪律：产品/插件的测试不进内核仓，单测框架用自带的 `tests/unit/ithaca_test_framework.hpp`（CHECK 宏），不引 gtest。

## 2. e2e 必须走 host fixture（tests/e2e/helpers/host.mjs）

```js
import { test, expect, getJson, postJson } from "./helpers/host.mjs";
test("SC1 …", async ({ host, page }) => { … })
```

fixture 已内置（不要自己重造）：

- **每用例独立宿主 + 隔离 home**（`tests/.tmp/<用例名>_home`），端口按 workerIndex 错开；并行安全，禁止 `taskkill /IM` 全局杀（只许按 PID `/T`）。
- `hostCfg.scenario`：mock 剧本（默认 = 写 hello.txt 后收口）；`hostCfg.seed`：启动前种文件（如孤儿 index.json）；`hostCfg.pickStub`：启用 `ITHACA_TEST_PICK_PATH` 钩子，固定选 `ws/picked-ws`。
- 默认种 `{"provider":"mock"}` 到 config.json——全新 home 的配置迁移会把 Mock 置 disabled、指向无 key 云端 ⇒ turn 必然「LLM 不可用」。除非用例专门测配置迁移，否则不要绕开这个种子。

## 3. 等待纪律（时序类失败的大头）

- **等事实，不等时间**：turn 收口 = 轮询 `/api/transcript` 出现 `assistant` 记录；不用固定 sleep 等业务事件（fixture 的 waitReady 除外）。
- **in_flight 门卫**：turn 进行中 new/open 一律被拒（200 + ok:false）。需要调创建/切换类端点的用例，先等上一个 turn 收口，否则拿到的是门卫响应不是目标语义。
- **断言状态码时注意门卫优先级**：`in_flight` 检查在 message 校验之前——裸 new 的 400 断言必须在无 turn 进行时发起。

## 4. UI 层专项

- 浏览器直达 webui 的 HTTP 页面，**不驱动 WebView2 壳**；`channel: "msedge"`（零下载），headless 默认。
- 选择器用组件里稳定的 class：`.new-chat`、`.hero-ws`、`textarea.in`、`.send-btn`、`.sess .t`、`.sess.active`、`.msg.u/.msg.a`。新增可测点优先复用，确需新钩子时加语义 class，不加 `data-test-*`（跟随现有风格）。
- **请求面断言**（API 层给不了的）：`page.on("request")` 收集，如「草稿期零 `POST /api/session/(new|assign)`」。前端行为用例（零请求、切走丢弃）在 UI 层正面断言，API 层只测镜像不变式（服务端拒绝、注册表无孤儿）。
- 关窗/重启语义：草稿丢弃用 `page.reload()`；重放一致性 = `host.stop(); host.start(); await host.waitReady(); page.reload()`。

## 5. 产品码测试钩子纪律

钩子是产品码里的正式 seam，从严控制：一律环境变量触发（如 `ITHACA_TEST_PICK_PATH`）、默认关闭、走与真实路径相同的事件/管线（钩子返回 folder_picked 事件，而非绕过它）。新钩子先在本文件登记再实现。

## 6. 验证与接线

- 新测试必须挂进 npm：单测自动进 `npm test`；e2e 进 `e2e:session` / `e2e:ui`（--project 区分）；一键全量 = `npm run check`（build → regress → e2e:all）。没接线的测试视为不存在。
- 评测基准 `npm run eval`（上下文压缩 A/B 指标）不在验证链内：测压缩效果不测对错，改折叠逻辑后手动跑，报告落 `tests/.tmp/eval/report.json`。
- **`tests/.tmp` 保留上界 = 最近一轮 e2e**：playwright globalSetup（`tests/e2e/helpers/global-setup.mjs`）在每轮启动时清空白名单（`eval/`）外的全部目录——失败现场只活到下次运行为止；非 fixture 产出方（手工调试脚本、单测）无需自带收尾。并发两轮 e2e 会互清对方在途目录，check 链必须串行。
- 修 bug 的配比惯例：**两层各补一条**——单测锁函数行为，e2e 锁用户可见行为，防止以任何形式复发。
- 提交前验证命令固定顺序：`npm run check`，输出全绿才可提交；时序抖动导致的偶发失败先修等待逻辑，不许靠 retries 掩盖（retries: 1 只是兜底）。

## 7. 已知坑（写用例前过一眼）

- 前端 `api()` 无 body ⇒ 发 **GET**——POST 端点必须显式传 `{}`（真实踩过：pickFolder 404 静默无效）。
- handle 栈内禁 broadcast（EDEADLOCK）；插件侧一律 `poster_submit` defer。
- 全新 home 直接建会话必失败（LLM 不可用），见 §2 的 config 种子。
- index.json 落盘只在轮次边界与显式操作时发生，断言注册表状态后要容忍半个 turn 的滞后。
